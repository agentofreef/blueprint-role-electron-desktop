# 视觉方向与产品 UX

## CP2 视觉方向

Taste 读取产品定位、结合项目已有视觉风格查找参考。说明哪些构图、排版、色彩、密度和动效原则来自参考，哪些决定针对本应用的工作场景。交付至少一个代表性桌面屏。复杂产品增加具有不同交互形态的代表屏，覆盖主任务、侧栏、工具栏、菜单与实际窗口比例。项目要求时覆盖浅色、深色和多窗口。

将方向、依据、代表屏及待决定事项提交审批，记录到 `VISUAL_DIRECTION.md` 或等价文档。

## CP3 设计系统

Impeccable 依据当前安装版本的真实命令和指南收敛设计。把通过的方向写入 `DESIGN.md`，沿用适用主题与组件，补齐受影响的缺口。

- 定义色彩、排版、间距、圆角、边框、阴影、图层、动效和布局约束。
- 将按钮、导航、表单、列表、表格、卡片、对话框与提示映射到实际组件。按任务覆盖默认、悬停、焦点、选中、禁用、加载、空态和失败。
- 定义键盘、焦点、快捷键和减少动态效果。说明侧栏调整、拖放、上下文菜单及窗口尺寸变化在何处由 Renderer 或 OS 实现。
- 交付代表 UI、组件映射、无障碍与回归条件。与 MAIN 的依赖图和验证方案一并送审。

## 实测后的审查

Taste 对照已批方向审核实际应用的构图、一致性和辨识度。Impeccable 对照设计系统审核层级、行为、状态和可访问性。用可复现的截图和路径写问题。MAIN 确定影响与修复顺序，工程修复后由 QA 重走对应流程。
