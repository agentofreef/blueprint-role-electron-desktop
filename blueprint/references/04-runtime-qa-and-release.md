# 实际运行、回归与发布

## 测试与证据

用项目支持的方式启动实际 Electron 应用。尽量使用隔离测试资料。确认窗口加载、Renderer 和 Main 真实通信及无关键运行错误。使用 agent-browser 连接受控的 Chromium 调试目标，走用户的主任务、导航、表单、对话框、异步、空态、失败、键盘及窗口调整。用项目现有方法或 OS 级机制补测原生菜单、托盘、系统对话框、快捷键和文件选择。

每个用例记录应用版本与平台、初始状态、操作、预期、实际结果、状态和证据路径。在适当的 QA 目录保存实际截图，例如 `artifacts/qa/feature-initial.png`、`feature-interaction.png`、`feature-final.png`。区分单元、集成、实际运行和包级验证。已执行才可标记通过，受环境限制的项目写清未验证范围。

维护受影响的回归清单。变更共享组件、导航、状态、窗口、IPC、数据、权限或鉴权时复跑对应既有路径。每个完成的里程碑应能指向其适用的单元、集成、运行、视觉和回归结果。

## 缺陷反馈

记录缺陷编号、严重度、复现路径与截图、影响、拟修复方案、负责人和复测方式。P0 是关键产品或安全问题，P1 是重大功能或 UX 缺陷，P2 是明显设计和交互缺陷，P3 是细节。发布前修复 P0 和 P1，解决 P2 或取得明确接受，说明延后 P3 的理由。每次修改后按影响面复测，更新 QA 和计划。

## CP5 审阅材料

- 功能验收矩阵、架构与安全核对、设计审查、运行 QA 和持续回归。为每项声明附上证据或限制。
- 构建版本、包验证、适用平台的启动和安装／卸载、签名、公证或更新结果。记录未运行的环境和剩余风险。
- 计划状态、仍需决定的事项和一次明确的发布验收请求。保留真实审批和最终决定。

使用 `QA_PLAN.md` 与 `QA_REPORT.md`，或现有的同类文件。外部发布范围以用户和仓库授权为准。
